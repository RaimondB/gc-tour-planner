# Requirements — Cache ingest

How caches enter the system. Cross-references: [design/data-model.md](../design/data-model.md) for the `caches` schema; [design/gpx-parsing.md](../design/gpx-parsing.md) for the parser.

- **FR-I1.** Accept GPX upload via the web UI. Parse Groundspeak Pocket Query extensions (`groundspeak:cache`, `groundspeak:attributes`, `groundspeak:short_description`, `groundspeak:long_description`) **and** generic GPX waypoints.
- **FR-I2.** Identify and store **additional waypoints** with `type='parking'` (Groundspeak `<sym>Parking Area</sym>`) per cache.
- **FR-I3.** Upsert by `(source, source_id)` so re-uploading a refreshed PQ updates instead of duplicating.
- **FR-I4.** Per-user row-level isolation: a user only sees caches they uploaded (or that came from a public source adapter).
- **FR-I5 (M7).** Optional **OKAPI** source adapter for OpenCaching nodes, queryable by bbox.
- **FR-I6 (M8, feature-flagged off).** GC.com partner-API adapter — single shared partner key from env; never per-user creds in DB.
- **FR-I7 (record finds).** The user can record which caches they have found, via two paths:
  - Uploading a Groundspeak **"My Finds"** Pocket Query GPX — every cache in the upload is also marked as found by the current user (idempotent; re-uploading does not duplicate). **A "My Finds" PQ is auto-detected** from its top-level `<gpx><name>My Finds Pocket Query</name>` (matched case-insensitively, captured as `ParsedGpx.isMyFinds`); the upload marks the finds automatically with no manual toggle. The `markAsFound` request flag remains as a manual override to mark a _regular_ PQ's caches as found. The upload response carries `myFinds: boolean` so the UI can confirm the detection.
  - **Manual mark / unmark** from the map popup of any cache they own. Finds are per-user; another user does not see them.
- **FR-I8 (precompute on upload).** GPX upload completion triggers two background jobs, fire-and-forget from the upload handler's perspective: `walking-precompute` (OSRM `/table` for each new cache's top-k haversine neighbours within 3 km + re-runs k-NN for affected existing caches, persists to `route_legs`) and `overpass-refresh` (landuse around the new caches' convex hull into `osm_landuse`). Uploads must not block on precompute. Per-cache freshness is tracked in `cache_precompute_state` so stale rows can be retriggered without purging the whole cache. See [ADR-0007](../adr/0007-precompute-walking-paths-on-upload.md) and [design/precompute.md](../design/precompute.md).
- **FR-I9 (raw upload preservation).** Every uploaded `.gpx` is persisted gzipped on disk at `{UPLOADS_DIR}/{uploadId}.gpx.gz` (docker volume `gctp-uploads` in compose stacks; `./data/uploads/` in `scripts/dev.sh`). The `gpx_uploads` row carries `raw_size_bytes` + `raw_sha256` (over the uncompressed XML) so reprocessing has an integrity reference. Storage happens before parse, so even uploads whose parse fails are preserved — the operator can fix the parser and retry. The admin endpoint `POST /admin/uploads/:id/reprocess` re-reads the stored bytes, re-parses, and re-upserts caches using the same path as the original upload. Use case: when the parser learns about a new field (FR-I10's `disabled` was the first), reprocessing historical uploads back-fills the column without asking users to re-upload. Per-owner isolation: an upload id belonging to a different user returns 404 (indistinguishable from "does not exist").
- **FR-I10 (cache availability — disabled + archived + staleness guard).** Three orthogonal additions to the cache lifecycle:
  1. **Parse + persist `disabled`.** Groundspeak GPX encodes the cache's current state via `<groundspeak:cache available="…" archived="…">`. The parser maps `available="False" + archived="False"` to `caches.disabled = TRUE` (temporarily disabled by the owner — typically maintenance), and `archived="True"` to `caches.archived = TRUE` (permanently gone). The two booleans stay orthogonal so the UI can show exactly one badge per cache.
  2. **Default-hide both.** `listCaches` defaults to `WHERE NOT archived AND NOT disabled`. Supported by partial index `caches_owner_active_idx (owner_id) WHERE NOT archived AND NOT disabled`. The filter sidebar's "Include temporarily-disabled caches" chip flips `includeDisabled=true` and the map renders those at 50 % opacity with a "Z" overlay (geocaching.com convention — we cannot bundle Groundspeak icons per [LICENSING.md](../LICENSING.md), but the visual _language_ is unencumbered). Archived caches stay hidden unless an `includeArchived=true` query param is set; no UI surfaces this today.
  3. **Staleness guard on upsert.** Every PQ has a top-level `<gpx><time>` (Groundspeak emits it as the PQ generation timestamp). The parser captures it as `ParsedGpx.exportedAt`; the upload pipeline stores it on `gpx_uploads.exported_at` and copies it onto every upserted cache's `source_exported_at`. On re-upload, `upsertFromGpx` compares incoming vs. existing — if the incoming PQ is _older_ than the existing row, the cache is skipped (no overwrite). Null exportedAt on either side disables the comparison ("always allow"). Caches still appear in the upload's `cacheIdByCode` map (so downstream actions like mark-as-found still see them), but `outcome` reports them as `stale`.
- **FR-I11 (upload stats).** The upload response (`POST /gpx/upload`) carries `stats: { total, byType, disabled, archived, new, updated, stale, exportedAt }`. Drives the dropzone's "what just happened" summary block — per-type breakdown, count of new vs. updated vs. stale, count of disabled/archived caches in the upload, and the PQ generation timestamp. Pure function over the parser output + the per-row `outcome` map; no DB round-trips.
- **FR-I12 (upload dedup — store + process once).** A byte-identical file the same user already uploaded successfully is **not** stored or processed a second time. On upload the handler hashes the uncompressed XML (SHA-256) and looks for an existing `gpx_uploads` row by this owner with the same `raw_sha256` and `status='parsed'` (the column reserved for this in FR-I9). On a match it short-circuits — no second gzip on disk, no re-parse, no re-upsert — and the response carries `duplicate: true` with `uploadId` pointing at the existing upload and all counts/stats zero. The dropzone shows "already uploaded" with an **"upload anyway"** action that re-submits with `force=true`; `force` re-processes the _existing_ stored upload (re-parse + re-upsert against the same row, no second copy) rather than skipping. Dedup is scoped to `owner_id` (per-user isolation, FR-I4): a different user uploading the same bytes is processed normally. Distinct from FR-I3 (per-cache upsert by `(source, source_id)`) and FR-I10's staleness guard (per-cache timestamp compare) — this is whole-file dedup at the upload boundary. `gpx_uploads` stays tiny (< 1k rows lifetime), so the lookup needs no dedicated index.
- **FR-I13 (solved / corrected coordinates).** A user who has solved a Mystery (or knows a Multi's final location) sets _corrected coordinates_ on geocaching.com; the downloaded GPX then carries those corrected coords in the primary `<wpt>` **with no machine-readable marker** distinguishing them from posted coords. So the upload UI exposes a checkbox — `POST /gpx/upload` field `solvedCoordinates=true` — by which the user **asserts** the file holds solved coords. On such an upload:
  1. **Every cache in the file is marked solved.** `caches.solved = TRUE`, `caches.solved_at` is stamped, and the file's `<wpt>` coordinate becomes the cache's `location` — the coordinate the planner uses for radius/clustering/walking-graph. Applies to any type (Mystery solutions and Multi finals alike).
  2. **The original posted coordinate is kept.** A normal PQ records its `<wpt>` in `caches.published_location`; a solved upload never overwrites `published_location`. Conversely a normal PQ refreshes `published_location` + metadata but **never** overwrites a solved cache's `location` — the two upload modes write disjoint columns, so re-running a weekly PQ can't clobber a solved coordinate, and solved uploads bypass the FR-I10 staleness guard (they're a deliberate assertion).
  3. **Removable.** `DELETE /caches/:id/solved-coordinates` reverts `location = COALESCE(published_location, location)` and clears `solved`. (When the cache was first seen via a solved upload there's no posted coord to revert to, so `location` stays put.)
  4. **Precompute follows the coordinate.** Setting, refreshing, or removing a solved coordinate _moves_ the cache, so the upsert/clear path invalidates that cache's `route_legs` + `cache_landuse` in the same transaction and the walking-precompute re-warm recomputes them — the precompute's freshness filter would otherwise treat the stale legs as current. See [design/data-model.md](../design/data-model.md) and [design/precompute.md](../design/precompute.md).
- **FR-I14 (machine ingestion API — programmatic GPX upload).** A trusted non-browser client (a script, a scheduled job, or an external source adapter) can upload GPX cache files without the browser session. `POST /ingest/gpx` accepts the same multipart `file` (+ optional `markAsFound` / `force` / `solvedCoordinates` flags) as `POST /gpx/upload` and reuses the **same** ingest path (FR-I3 upsert, FR-I10 staleness guard, FR-I12 dedup, FR-I8 precompute) — it differs only in **authentication**: a bearer token in the `Authorization` header, **not** a session cookie, and therefore CSRF-exempt (a bearer is not an ambient credential). Caches are attributed to the **token's owner**, never a request-supplied id, so there is no on-behalf-of escape. Auth is the `@MachineAuth()` + `IngestAuthGuard` pair on a route that is **not** `@Public()`; the no-session surface is pinned by its own normative inventory (`machine-auth-inventory.spec.ts`), the machine-auth sibling of the FR-P11 public-route inventory. The shipped credential is a single shared key (`INGEST_API_KEY` → `INGEST_OWNER_ID`), env-only and never in the DB (the M8 partner-key pattern, [FR-I6]); the guard resolves token → owner through an injectable seam (`IngestTokenResolver`) so a future DB-backed per-user token store supersedes it without changing the client contract. The same seam serves any future sanctioned source (OKAPI [M7], a GC.com API adapter [M8]). Disabled by default (`INGEST_API_ENABLED`, off); when enabled, `INGEST_API_KEY` + `INGEST_OWNER_ID` are required at boot. See [ADR-0033](../adr/0033-machine-ingestion-api.md) and [design/auth-and-sharing.md](../design/auth-and-sharing.md).

## Environment knobs

Machine ingestion API (FR-I14). Env-only, no DB; real prod values stay in the gitignored prod `infra/.env`, never tracked.

| Var | Default | Meaning |
| --- | --- | --- |
| `INGEST_API_ENABLED` | off | Master switch. When unset/`0`, no machine route is exposed. |
| `INGEST_API_KEY` | — | Shared bearer token presented by source adapters. Required when enabled. |
| `INGEST_OWNER_ID` | — | `users.id` all machine-ingested caches are attributed to. Required when enabled; a value with no matching user logs a soft startup warning. |
