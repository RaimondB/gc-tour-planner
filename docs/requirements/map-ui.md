# Requirements — Map UI

MapLibre + filter sidebar + attribution. See [design/frontend.md](../design/frontend.md) for layer naming and component layout.

- **FR-M1.** MapLibre GL JS map with cache markers (clustered at low zoom), landuse polygon overlay (toggle), planned tour polyline, parking marker.
- **FR-M2.** Collapsible filter sidebar; map and sidebar always reflect the same query state.
- **FR-M3.** Display OSM attribution ("© OpenStreetMap contributors") on every map view.
- **FR-M4.** Attribute icons must be free-license (Material Symbols / text chips) — **never** bundle Groundspeak's copyrighted icons.
- **FR-M5 (search radius visible on map).** Render the current search radius as a non-interactive circle overlay around the active search center. The overlay updates immediately as the user changes the center or the radius. In the Find step (FR-M6) the circle is pinned to the viewport centre (a reticle); outside it the circle is frozen, dimmed, at the last committed centre. **Changing the radius in the Find step refits the camera** (debounced) so the whole circle stays visible as it grows or shrinks.
- **FR-M6 (set center by panning — reticle model).** In the Find step the search circle is a **viewport-centred reticle**: the user **pans the map to aim**, the circle stays pinned to screen centre while caches slide underneath, and the search center is committed to the map centre when the camera settles (`moveend`). A background **tap does not set the center** (it never did double duty with cache popups again — see ADR-0024). Sidebar inputs reflect the committed value; the camera does **not** jump on commit (panning was the user's choice). A near-stationary tap on a cache still opens its popup; a tap that is really the tail of a pan (moved beyond a small pixel threshold) is ignored. [ADR-0024](../adr/0024-reticle-map-interaction.md)
- **FR-M7 (geolocate flies the camera).** Activating **Use my location** updates the search center _and_ flies the camera there at a sensible zoom (≈ radius-fitting). Sidebar inputs reflect the new value.
- **FR-M8 (decimal-dot lng/lat inputs).** Longitude and latitude inputs always display and accept `.` as the decimal separator, regardless of browser locale. (Comma input is also accepted as a convenience and normalized on commit.)
- **FR-M9 (OSM parking overlay).** Render OSM `amenity=parking` features (ADR-0011) from `GET /parking-facilities`: polygons (fill + outline) for way/relation parkings, circles for node parkings, "P" / "P€" text labels at high zoom. Style is keyed on `(access, fee)` — green for free public, blue for paid public, grey for customers, orange for permit. Layer is **viewport-following** (refetches on `moveend`, debounced + grid-snapped) and shares its visibility threshold with the cache-owner parking pins via a single `PARKING_MIN_ZOOM` constant. Sidebar exposes access (`yes`, `customers`, `permit` opt-in) and fee (`free` / `paid` / `any`) filter chips that drive both the rendered layer and the `osm-parking` start mode.
- **FR-M10 (viewport-following overlays).** Landuse, OSM parking, and the walking-graph debug overlay all follow the current map viewport — they refetch the visible bbox on pan/zoom rather than rendering the whole search radius. The bbox is grid-snapped so small pans don't refetch, and each layer clears its rendered features when the user zooms below its `minZoom` so the canvas matches the (no-)fetch state.
- **FR-M11 (state persistence).** Search filters, planner settings, and the map viewport survive a hard refresh via `localStorage`. Storage keys are prefixed `gctp:` so the user can purge them if state gets corrupted.
- **FR-M12 (compositional, colour-blind-safe markers).** Every cache / AL stage is drawn as **base (shape = kind) + centre label + context rings + reserved corner badges** ([ADR-0035](../adr/0035-compositional-marker-model.md)). **Shape** encodes kind (geocache = circle, Adventure Lab = squircle); **colour** encodes type and is *preserved across every context* (a Mystery stays blue in a tour); an **inner letter** repeats the type so colour is never the only channel. The revised `TYPE_COLORS` palette has no duplicate hex and one green (locked by a unit test).
- **FR-M13 (reserved corner-slot adornments).** Status cues sit in four fixed corners and never collide: **TR** tool-required (a wrench *icon*), **TL** solved-coordinate `✓`, **BL** disabled `Z`, **BR** the demoted identity badge. **Status adornments are icons, identity is letters** — a status badge can never be mistaken for a type letter.
- **FR-M14 (uniform tour numbering + tour ownership).** In a routed tour the **centre of every stop is its visit-order number** (regular and AL alike); the cache's identity (type letter / `S{n}`·`L{n}`) demotes to the BR corner. The tour OWNS its caches: routed stops + dropped candidates are hidden in the caches layer (the click/popup target stays) so `TourLayer` is the single authority — no double-draw or `S{n}`-over-order. Dropped candidates are **greyed out** (kind shape + identity letter still show what was skipped) with no number, and collapse on zoom like the stops.
- **FR-M15 (context hierarchy — no mode bleed).** Precedence is `tour > cluster > plain`. When a tour is active the cluster preview de-emphasises and stops forcing its centroids above the tour, so a cluster centroid never floats over a routed loop.
