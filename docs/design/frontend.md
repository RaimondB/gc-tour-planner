# Frontend implementation notes

- **TanStack Query keys** mirror endpoint shape: `['caches', { center, radiusM, types, attributes, contexts }]`. Layer-specific keys include the snapped viewport bbox so a small pan inside a tile doesn't bust the cache (see `useViewportBbox` below).
- **State persistence.** Three pieces persist to `localStorage` via `useLocalStorageState` ([apps/web/src/lib/persistent-state.ts](../../apps/web/src/lib/persistent-state.ts)) so a hard refresh restores the user's spot:
  - `gctp:search` — filter sidebar (center, radius, types, contexts, excludeFound).
  - `gctp:plan-settings` — planner sidebar (start mode — default `auto` — OSM-parking filters, link cap, budgets, fringe trim, topN).
  - `gctp:viewport` — map center + zoom (decoupled from `params.center` so panning around to browse doesn't churn the search).
- **Viewport-following data layers.** [apps/web/src/features/map/useViewportBbox.ts](../../apps/web/src/features/map/useViewportBbox.ts) listens to `moveend`, debounces, snaps the bbox to a fixed lat/lng grid + pads by one cell, and exposes it as React state. Three layers consume it (Landuse, OsmParking, WalkingGraph). Below each layer's `minZoom` the hook returns `null` — the layer's render effect then sets its GeoJSON source to an empty FeatureCollection so the previously-fetched data is cleared (otherwise a zoomed-out view would still render the snapshot from the zoomed-in fetch).
- **Map layers** (MapLibre source/layer ids):
  - `gctp-caches` / `gctp-caches-circle` — regular caches as **circles** (kind = shape), radius interpolated by zoom (z9→4 px / z14→9 px), fill = the type colour. AL stages render via `gctp-caches-al-circle` as a purple **squircle** icon (ADR-0035 — circle vs squircle is the colour-blind-safe kind channel). `gctp-caches-center-label` draws the centre glyph — the type letter for a cache, `S{n}`/`L{n}` for an AL stage. Status badges sit in reserved corners: `gctp-caches-tool-badge` (wrench, TR), `gctp-caches-solved-badge` (`✓`, TL), `gctp-caches-disabled-label` (`Z`, BL). Collapsed adventures: `gctp-al-adventure-*` (squircle pin + `×N`). The shared palette / glyphs / corner offsets / ring styles / generated marker images live in [marker-style.ts](../../apps/web/src/features/map/marker-style.ts); the pixel-proximity collapse shared with the tour is [marker-collapse.ts](../../apps/web/src/features/map/marker-collapse.ts) (wraps `pixel-cluster.ts`). When a tour is active, caches it owns (routed + dropped) are hidden here (the `gctp-caches-hit` target stays, so the popup still opens) — see ADR-0035.
  - `gctp-landuse` / `-fill` / `-line` — semi-transparent polygons, kind-coloured. Viewport-following, z8+.
  - `gctp-osm-parking` / `-fill` / `-line` / `-point` / `-label` — ADR-0011 OSM parking. Polygons + node circles + `P` / `P€` text labels, styled by access + fee. Viewport-following, z `PARKING_MIN_ZOOM` (currently 12) and above. Click → popup with raw OSM tags.
  - `gctp-parking-circle` — cache-owner parking (`additional_waypoints.type='parking'`). Shares `PARKING_MIN_ZOOM` with `OsmParkingLayer` via [apps/web/src/features/map/parking-zoom.ts](../../apps/web/src/features/map/parking-zoom.ts), sized smaller than the cache circle so the cache stays the headline feature.
  - `gctp-parking-preview-*` — ADR-0011 walking previews per cluster (dashed lines, red = bogus = exceeded `maxLinkMeters`, blue = OK).
  - `gctp-parking-owner-link-line` — yellow dotted straight line from any clicked parking marker to the cache that listed it.
  - `gctp-start-pick-*` — amber "P" preview of the map-picked start point (`startPreference="user-supplied-point"`), shown until a tour is planned (then `gctp-tour-parking-*` takes over). Click routing for setting it lives in `App.tsx` `onPickCenter` and takes precedence over the per-step click behaviour.
  - `gctp-tour-*` — chosen-plan polyline + routed stops. Each stop keeps its **type colour + shape** (circle, or `gctp-tour-stops-al-icon` squircle for AL — ADR-0035), not a blanket red; red survives only as the line/arrow accent. The centre shows the **visit-order number for every stop** (`gctp-tour-stops-label`); the cache's identity (type letter / `S{n}`·`L{n}`) demotes to the BR corner (`gctp-tour-stops-identity`), and the tool wrench to TR (`gctp-tour-stops-tool`). Dropped candidates (`gctp-tour-dropped-*`) are **greyed out** (`#757575`; kind shape + centre identity letter still show what was skipped) with no number, and collapse on zoom like the stops. Overlapping stops collapse via `marker-collapse.ts` into `gctp-tour-stops-collapsed-*` (range/`×N` label). The chosen parking is `gctp-tour-parking-circle`/`-label`: blue **"P"** normally, **red "P?"** when `ParkingChoice.fallback` is set (no feasible parking found). When the parking marker lands within ~22 px of a stop it's offset by a fixed pixel translate and a `gctp-tour-parking-leader-line` connects it back to its true location (recomputed on zoom/move). `triggerRepaint()` is called after every source mutation because MapLibre otherwise skips the redraw when the map is quiescent.
  - `gctp-walking-graph-*` — debug overlay (planner sidebar toggle).
- **`ZoomDebugBadge`** ([apps/web/src/features/map/ZoomDebugBadge.tsx](../../apps/web/src/features/map/ZoomDebugBadge.tsx)) renders a small bottom-left overlay with the current zoom + center coords for tuning per-layer thresholds without DevTools.
- **Score breakdown panel** is always visible after planning. Each row: constraint name, weight, contribution, sign.
- **Auth + routing (M6).** TanStack Router is introduced for the first time: public routes `/login`, `/register`, `/shared/:slug` vs. the protected `/` (today's `App.tsx`). An `AuthProvider` exposes `useAuth()`, backed by a `['auth','me']` query over `GET /auth/me`; protected routes redirect to `/login` when unauthenticated. `api.ts` gains `credentials: "include"`, reads the non-httpOnly `csrf` cookie and sends it as `X-CSRF-Token` on POST/PATCH/DELETE, and a central interceptor maps 401 → `/login`. The `/shared/:slug` view reuses `MapView`/`TourLayer`/`CachesLayer` read-only (no edit/save). See [auth-and-sharing.md](auth-and-sharing.md).
- **PWA / installability (FR-W1–W4, [ADR-0028](../adr/0028-pwa-installability-offline-and-native-share.md)).** `vite-plugin-pwa` (+ workbox) builds the manifest + service worker; the `manifest` object lives in `vite.config.ts`. Self-hosted icons in `apps/web/public/icons/` (192/512 + maskable, rendered from `icon-source.svg`/`icon-maskable.svg`; no CDN). The SW is registered via `virtual:pwa-register/react` in [PwaUpdatePrompt.tsx](../../apps/web/src/features/shell/PwaUpdatePrompt.tsx), which shows a `prompt`-strategy "update available" toast (its presentational view is split into [pwa-update-toast.tsx](../../apps/web/src/features/shell/pwa-update-toast.tsx), which collapses to a full-width, safe-area-aware bottom bar on mobile). Install is **not** a toast: [PwaInstallProvider.tsx](../../apps/web/src/features/shell/PwaInstallProvider.tsx) captures `beforeinstallprompt` once above the router and exposes `usePwaInstall()` (`canInstall` / `promptInstall`); `App.tsx` renders it as a header button on desktop and an "Install app" item in the hamburger menu on mobile, so it never covers the map. The install/update layouts can be eyeballed offline via the dev visual harness `dev/pwa-preview.html` (`apps/web/scripts/shoot-pwa-preview.mjs` screenshots it at mobile + desktop widths — no API/auth/SW needed). Workbox runtime caching: `NetworkOnly` for `/api/*`, except the saved-tour reads (`/tours`, `/tours/:id`, `/tours/:id/preview`) on `StaleWhileRevalidate` for offline viewing. nginx serves `sw.js` + `manifest.webmanifest` with `Cache-Control: no-cache`.
- **GPX download (FR-W2, [ADR-0032](../adr/0032-service-worker-mediated-gpx-download.md)).** [lib/gpx-download.ts](../../apps/web/src/lib/gpx-download.ts) `downloadGpx` prefers a **service-worker-mediated download** ([lib/sw-download.ts](../../apps/web/src/lib/sw-download.ts)): it stages the GPX as a `Content-Disposition: attachment` `Response` in the `gpx-downloads` cache and a hidden iframe fetches it via a workbox `CacheFirst` route on `/_gpx/*` — the only way to reliably save a file inside an Android installed PWA (where in-page anchor/blob `download` is swallowed), and it works offline. Falls back to [lib/download-text.ts](../../apps/web/src/lib/download-text.ts) (deferred-revoke anchor) when no SW controls the page. A pure-confirmation toast ([GpxDownloadToast.tsx](../../apps/web/src/features/shell/GpxDownloadToast.tsx)) names the saved file; the name follows [lib/tour-filename.ts](../../apps/web/src/lib/tour-filename.ts). Web Share is not used (Chromium's allowlist rejects `.gpx`). Wired into the GPX buttons in `App.tsx` and `PlannerSidebar.tsx`.
- **Map snapshot + offline tours (FR-W3/W4).** `MapView` sets `canvasContextAttributes.preserveDrawingBuffer: true` so [lib/map-snapshot.ts](../../apps/web/src/lib/map-snapshot.ts) can `toBlob` the canvas (basemap + overlays) to WebP. On save (and as a backfill on first online open of older tours) the snapshot is uploaded via `saveTourPreview` (`PUT /tours/:id/preview`) and invalidates the `["tours"]` query so the My-Tours thumbnail appears immediately. The snapshot is also the **offline map fallback**: [lib/use-connectivity.ts](../../apps/web/src/lib/use-connectivity.ts) probes `GET /api/health` (NetworkOnly) for authoritative connectivity — re-checked on online/offline events, tab focus, an interval, and on demand when `MapView`'s `onBasemapError` fires (tiles failed). `App.tsx` overlays the stored snapshot (with OSM attribution) when offline. This is decoupled from tile rendering, so cached tiles don't make it flap. Map tiles themselves are **not** SW-cached (OSM tile policy). Capture is best-effort — a CORS-tainted canvas (tile host without CORS headers) just skips it.
